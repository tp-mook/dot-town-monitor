# 実データ接続の設計

UI 試作（`prototype/index.html`）をデモデータから実データに切り替えるための設計です。
最初の監視対象は会社 HP（https://www.vision-marketing.co.jp/ ）。

## 1. 前提：会社 HP は Wix で、アクセスログが取れない

調べた結果（2026-10-27）:

- 配信は Wix（応答ヘッダーに `x-wix-request-id`、前段は Wix が管理する Cloudflare）
- DNS も Wix（`ns4.wixdns.net` / `ns5.wixdns.net`）

このため、

- Apache / nginx のような**生のアクセスログは取り出せない**
- 自分の Cloudflare などを前に置いてログを取る方法も**使えない**（DNS と証明書を Wix が握っている）

そこで、データの入口を 2 つ用意し、どちらも同じ「イベント」形式に変換してから先の処理を共通にする。

| 入口 | 対象 | 取れるもの | 取れないもの | 段階 |
|---|---|---|---|---|
| **A. 計測タグ** | Wix など、ログが取れないサイト | 人の動き（ページ、滞在時間、来訪元、端末、再訪） | クローラー・営業ロボット・攻撃者（JavaScript を動かさないため） | 第 1 段階 |
| **B. アクセスログ** | 自社サーバー・VPS（Apache / nginx） | 上記に加えて、ロボット・攻撃者、404、ログイン試行 | — | 第 2 段階 |

会社 HP は A で始める。そのため、会社 HP の町では**防犯の表示（要注意の相手・赤いフード）は出ない**。
画面には「この町は計測タグで見ています（ロボット・攻撃者は映りません）」と表示する。
防犯の機能は B（アクセスログ）につないだサイトで使う。

## 2. 全体の流れ

```
[Wix HP] ─ 計測タグ ─ HTTPS POST /collect ─┐
                                          ├→ 正規化 → 判定 → 訪問のまとまり化 → 保存 → 配信 → [町の画面]
[nginx/Apache] ─ ログ送信/取り込み ─────────┘      (人/ロボ/   (誰が・どの順に)   (DB)   (API)
                                                   営業/攻撃)
```

- **正規化**：入口ごとの形式を、下の「共通イベント」にそろえる
- **判定**：人・クローラー・営業ロボット・攻撃の疑いに分ける（5 章）
- **訪問のまとまり化**：同じ人の一連のページ閲覧を 1 回の訪問にまとめる（30 分あいたら別の訪問）
- **配信**：画面は数秒ごとに新しいイベントを取りにいく（最初は単純なポーリング。必要になったら常時接続にする）

## 3. 収集サーバーの置き場所（要決定）

計測タグからはインターネット越しに HTTPS で送るので、外から届く受け口が要る。

| 案 | 内容 | 費用の目安 | 長所 | 短所 |
|---|---|---|---|---|
| **A. Cloudflare Workers + D1**（推奨） | 受け口・保存・画面配信をすべて Cloudflare 上に置く | 無料枠内（Workers 10 万リクエスト/日、D1 書き込み 10 万行/日） | PC を止めても計測が続く。HTTPS が最初から使える | Cloudflare アカウントが必要。syslog は受けられない（ログ連携は別の方法で取り込む） |
| B. 社内 PC + Cloudflare Tunnel | Node.js のサーバーを PC で常駐させ、Tunnel で外に出す | 0 円 | 全部手元にある。syslog も受けられる | PC を常時起動しておく必要がある |
| C. VPS | Node.js のサーバーを VPS に置く | 月数百円〜 | 本番向き。syslog も受けられる | 契約と保守が要る |

推奨は A。第 1 段階（計測タグ）はこれで足りる。第 2 段階でログを syslog で受けたくなったら C を足す。
どの案でも中身の処理（正規化・判定・まとまり化）は同じコードを使えるように、置き場所に依存する部分（受け口・保存）を分けて作る。

## 4. 共通イベント形式

```jsonc
{
  "ts": "2026-10-27T11:32:05.120+09:00",
  "site": "vision-marketing",
  "source": "tag",            // "tag" | "log"
  "type": "page_view",        // page_view | page_leave | form_submit | request
  "visitor": "v_9f2c...",     // 訪問者の識別子（タグ: ブラウザに保存した乱数 / ログ: IP+UA のハッシュ）
  "session": "s_41ab...",
  "path": "/blog/ai-tips",
  "title": "生成AI活用術",
  "referrer": "https://www.google.com/",
  "ua": "Mozilla/5.0 (iPhone; ...)",
  "ip": "203.0.113.0",        // 保存時に末尾を伏せる（9 章）
  "status": 200,              // ログのみ
  "method": "GET",            // ログのみ
  "dwell_ms": 41000           // page_leave のときの滞在時間（タグのみ実測できる）
}
```

計測タグが送るのは `page_view`（表示したとき）と `page_leave`（離れたとき。`pagehide` と `navigator.sendBeacon` を使う）、お問い合わせフォームの送信時の `form_submit` の 3 種類。

## 5. 判定ルール

| 種類 | 判定のしかた | 入口 |
|---|---|---|
| 人 | 下のどれにも当たらないもの | A・B |
| クローラー | 名乗り（UA）の既知リスト（Googlebot, bingbot, GPTBot, ClaudeBot, PerplexityBot など）。B では逆引きで本物か確かめる | 主に B |
| 営業ロボット | ページをほとんど見ずにフォームへ送信する／同じ相手が短時間に何度も送信する | A（一部）・B |
| 攻撃の疑い | 404 の連打（例：1 分に 10 回以上）、下見の定番パス（`/wp-login.php`, `/.env`, `/xmlrpc.php`, `/phpmyadmin` など）、同じ相手が多数の名前（UA）を使い分ける、ログイン失敗が続いたあとの成功 | B |

しきい値は設定ファイルで変えられるようにし、サンプルログで調整する。

## 6. 小人の数値の取りかた

UI 試作で出している数値が、実データでどこまで取れるか。

| 項目 | A. 計測タグ | B. アクセスログ | 備考 |
|---|---|---|---|
| サイトにいる時間 | ○ | △ 最後のページの時間は不明 | |
| 見たページ数 | ○ | ○ | B は HTML のページだけ数える |
| ページごとの滞在時間 | ○ 実測 | △ 次のページまでの間隔で推定 | |
| これまでの訪問回数 | ○ ブラウザに保存した識別子 | △ IP+UA で推定 | |
| 検索した言葉 | **×** | **×** | Google などは検索語を渡さない。**UI を「検索エンジン名」に変える** |
| AI・SNS の来訪元 | ○ 来る前の URL から | ○ | |
| 端末 | ○ | ○ | |
| 見つからないページ | △ Wix の 404 ページにタグが入れば | ○ | |
| 要求回数・ログイン試行・名乗った名前の数 | × | ○ | 攻撃者の数値は B のみ |

## 7. 町の自動生成

- サイトの `sitemap.xml` を読み、各ページを家にする
- 区画の分け方：
  - URL に階層があるサイトは、1 階層目ごとに区画にする
  - 会社 HP（Wix）は `/会社概要` `/ledビジョン販売` のように階層がない。そこで、Wix が分けて出すサイトマップの種類（固定ページ・ブログ記事・ブログのカテゴリ・実績）で大きく分ける
  - 固定ページは、設定ファイルで「製品（LED ビジョン）」「会社」「サポート」のように手で区画を割り当てる（最初に一度作れば、新しいページは「その他」に入る）
- 家の名前はページの `<title>` から取る（サイト名の部分は除く）
- ブログ記事のように数が多い区画は、人気の上位だけを家にし、残りは「ほか N ページ」の家にまとめる
- 新しいページが見つかったら家を足す。家の位置は一度決めたら変えない（見慣れた町が崩れないように）

## 8. 画面とのやりとり（API）

| API | 内容 |
|---|---|
| `POST /collect` | 計測タグからの受け口 |
| `GET /api/town` | 町のつくり（区画・家） |
| `GET /api/snapshot` | いまいる小人と、きょうの集計 |
| `GET /api/events?since=...` | 前回以降の新しいイベント（画面は数秒ごとに呼ぶ） |
| `GET /api/events?from=...&to=...` | 再生用の過去のイベント |

UI 試作の中の「デモデータを作る部分」を、この API を読む部分に差し替える。

## 9. 個人情報と公開リポジトリ

- IP アドレスは保存するときに末尾を伏せる（例：`203.0.113.0`）。攻撃の判定に使う生の IP は B だけで、30 日で消す
- 計測タグの識別子は乱数で、氏名などは取らない
- 計測タグを入れるにあたって、プライバシーポリシーへの追記が要るかを確認する（識別子をブラウザに保存するため）
- 画面には合言葉をかけ、社内の人だけが見られるようにする
- **このリポジトリは公開**なので、合言葉・API キー・サイト固有の設定はコミットしない（`.env` と Cloudflare の secrets に置く）

## 10. 進める順番

1. 収集サーバーのひな形と計測タグを作り、ローカルで模擬データを送って町が動くことを確かめる
2. 収集サーバーを置き場所に出し、Wix に計測タグを入れる（Wix の「カスタムコード」。有料プランで使える機能）
3. 会社 HP の実データで町を動かし、`sitemap.xml` から町を自動生成する
4. アクセスログ（B）の取り込みと防犯の判定。サンプルログで検証する

## 決まったこと・進み具合

- 収集サーバーは **Cloudflare Workers + D1**（2026-10-27 決定）
- 1 はできた（2026-10-27）。ローカルで次を確かめた
  - サイトマップから会社 HP の 43 ページを取り込み、区画に分けて町を作る。ページの `<title>` も取る
  - 模擬の訪問者を送ると、画面に小人が出て歩き、記録・集計・小人ごとの数値が実データで出る
  - 計測タグを確認用ページで動かし、ページの切り替え（読み込み直しなし）・滞在時間・フォーム送信・離脱が届く
- 区画は `sites/vision-marketing.json` のルールで割り当てる。実績ページの名前には顧客名が入るので、ページ名そのものはリポジトリに書かない

- 2 のうち収集サーバーの公開はできた（2026-10-27）。https://dot-town-monitor.vision-marketing.workers.dev/
  - 本番で確かめたこと：合言葉なし・ちがう合言葉は 401、会社 HP 以外からの送信は 403、サイトマップ 43 ページの取り込み、会社 HP を名乗った試験送信が画面の API まで届く（試験データは削除済み）
  - 確認用ページ（`public/dev/`）は本番には出さない（`public/.assetsignore`）

- 2 が終わった（2026-10-27）。会社 HP の Wix「カスタムコード」の「ボディ - 終了」に計測タグを入れた（すべてのページ・1 回だけ読み込む・コードタイプはアクセス解析）
  - 本番の会社 HP で、ページ表示・離脱・滞在時間・ブログ記事のタイトルが届くことを確かめた。リンクの移動・戻るも普段どおり動いた
  - 会社 HP（Wix Studio）は、リンクを押すとページ全体を読み込み直す。そのため、ページを移るたびに「離れた」が届く。画面は「離れた」のあと 10 秒待ち、次のページが届けば同じ小人として歩かせる
  - Cookie の同意バナーは出ていない（同意の設定が空）。同意バナーを付けると、同意した人だけが計測される

- 見直し（2026-10-27）
  - 画面の取得は「前回の続き」を番号で絞って読む。以前は毎回、溜まった全件を読み直しており、無料枠の読み取り上限（1 日 500 万行）にイベント約 170 件で届く計算だった
  - 取りにいく間隔：見ているとき 5 秒、隠れているとき 1 分、つながらないとき 30 秒。つながらないときは画面に「接続できません」と出す
  - 毎日の定期実行で、IP アドレスを 30 日、イベントを 400 日で消す
  - 別のタブから戻ったときは page_resume として送り、閲覧数に数えない
  - フォームは「送信」を押したあと、完了の文言が出るか入力内容が消えたときだけ送信とみなす（入力漏れでは数えない）
  - `?dtm=off` を付けて開いたブラウザは計測しない（社内の人の除外）
  - 受け口は同じ IP から 1 分 120 回まで。家にするのは区画のルールに当てはまるページだけで、既にある名前は書き換えさせない
  - Wix の 404 ページではカスタムコードが動かないので、タグではリンク切れ（迷子の穴）を見つけられない
